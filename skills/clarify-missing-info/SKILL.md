# 澄清缺失信息

## 目的

避免在信息不足时给出确定的尺码结论。**宁可多问一句，不要答错一次。**

## 输入

- `user_message`：用户本轮原话
- `session_slots`：本轮已确认的信息（见 memory.py 的 L1）
- `profile`：跨会话稳定偏好（L2）

## 必需槽位

| 槽位 | 必需性 | 说明 |
|---|---|---|
| `product_id` | **必需** | 用户指向的商品 |
| `height_cm` | **必需** | 身高 |
| `weight_kg` | **必需** | 体重 |

## 建议槽位（缺失时可用默认值，但要标注）

| 槽位 | 默认值 | 标注方式 |
|---|---|---|
| `fit_preference` | `regular` | "按标准版型建议…如您偏好宽松可告知" |
| `special_constraint` | 无 | 不主动问，用户提了才用 |

## 流程

1. 先查 `profile`（L2）是否已有身高体重 —— **有就不要问**。
2. 再查 `session_slots`（L1）本轮是否已说过 —— **有就不要问**。
3. 仍缺失时，按 `product_id → height_cm → weight_kg` 的顺序检查。
4. **一次只问一个缺失项**，且必须选择一个：
   - 优先问"当前最影响答案质量"的那个
   - 如果是商品不明确，先确认商品（问商品比问身高更重要）

## 关键规则

### 规则 1：一次只问一个问题

同时问"请问您身高多少、体重多少、平时穿什么码"会让用户流失。
问完一个，等回答，再问下一个。

### 规则 2：用户拒绝提供时，降级而不是纠缠

如果用户说"你就直接告诉我""不想说体重"，**不再追问**，改为：

> "好的。这款我给您一个参考区间：S 适合胸围 84cm 左右… 由于缺少您的具体数据，建议您对照商品页的尺码表再确认一下。"

**服从用户，而不是服从流程。**

### 规则 3：能从上下文推断的不要问

- 用户说"我 165 的个子" → 身高已有，不要再问。
- 用户说"跟上次那个一样的尺码" → 先去查 L3 历史。

## 输出

```json
{
  "action": "ask" | "proceed",
  "missing": ["height_cm"],
  "question": "请问您的身高大概多少呢？"
}
```

## 失败处理

- 商品不明确且用户无法说明 → 转 `escalate-to-human`。
- 用户连续两次回避同一问题 → 按规则 2 降级，不要第三次追问。
