# 记住用户偏好

## 目的

让对话有"复利"——用户说过一次的事，不应该再说第二次。

JD 里的说法是"建立长期、可积累的个性化用户理解"。**"可积累"三个字，落点就是这里。**

## 什么时候记 / 不记

| 信息 | 记？ | 层 | 理由 |
|---|---|---|---|
| 身高、体重 | ✅ | L2 | 稳定，下次一定用得上 |
| 版型偏好（紧/宽松） | ✅ | L2 | 稳定 |
| "上次 M 太紧" | ✅ | L3 | 含真实结果，权重最高 |
| 常穿尺码 | ✅ | L2 | 稳定 |
| 预算区间 | ✅ | L2 | 相对稳定 |
| **当前浏览的商品** | ❌ | L1 | 一次性，用完即弃 |
| **三围、健康状况、孕期** | ⚠️ | 不主动记 | 敏感属性。用户主动说的可以当轮使用，不落库 |
| **支付信息、地址** | ❌ | 绝不 | 安全红线 |

**判断标准只有一句：这个信息下次对话还用得上吗？**

## 写入规则

### 规则 1：每条记忆都要有来源和置信度

```json
{
  "field": "height_cm",
  "value": 165,
  "source": "user_stated",   // user_stated | inferred | purchase_history
  "confidence": 0.9,
  "updated_at": "2026-11-10T21:30:00"
}
```

| source | confidence 初始值 | 说明 |
|---|---|---|
| `user_stated` | 0.9 | 用户这轮明确说的 |
| `purchase_history` | 0.8 | 历史订单推断 |
| `inferred` | 0.5 | 模型推的，需再次确认才提升 |

### 规则 2：新信息与旧记忆冲突时，用新的，并提示更新

> 记忆：60kg（三个月前）
> 用户本轮："我最近胖了十斤"
>
> ✅ 正确："好的，那按 65kg 帮您重新看一下。要不要我更新一下您的档案？"
> ❌ 错误：继续用 60kg 算
> ❌ 错误：悄悄改成 65kg 不告知

**冲突处理三件套：用新的 → 说明变化 → 征得同意再落库。**

### 规则 3：用户纠正时必须能改

用户说"你记错了，我是 168 不是 165" → 立即更新，并确认"已经改成 168 了"。
**不能因为置信度高就拒绝更新。**

### 规则 4：不要把推断当事实存

如果只是根据用户"我比较瘦"推断出体重，`source` 必须是 `inferred`、`confidence` 0.5，
并且下次使用时要说"您之前提到偏瘦，我按 55kg 左右估算的"——而不是当成确定值。

## 输出

```json
{
  "writes": [
    {"layer": "L2", "field": "height_cm", "value": 165, "source": "user_stated", "confidence": 0.9}
  ],
  "conflicts": [],
  "user_notice": null
}
```

有冲突或更新时，`user_notice` 填入要对用户说的话。

## 失败处理

- 用户表达含糊（"我挺高的"）→ 记为 `inferred` 的低置信标签，不写具体数值。
- 用户明确说"别记我的信息" → 清空并停止写入，当轮仍可用，但不落库。
